# 怎麼加內容

## 一篇貼文 = 同一個編號的幾個檔案

根目錄長這樣，不用建任何資料夾：

```
011.txt      ← 第 11 篇的文案
011.jpg      ← 第 11 篇的圖
011-2.jpg    ← 第 11 篇的第二張圖
012.txt      ← 第 12 篇，純文字
013.mp4      ← 第 13 篇，影片
```

編號一樣就是同一篇，編號小的先發。

## 草稿不會被發出去

「新增一篇」建出來的檔案叫 `草稿016.txt`，程式看到「草稿」兩個字就會跳過，不會發。

**改好之後，把檔名的「草稿」兩個字刪掉**（變成 `016.txt`），它才會進隊列。同一個編號的圖片影片也會跟著一起等。

## 日常怎麼做

**只有文字**：雙擊「新增一篇」→ 寫 → 存檔 → 雙擊「同步到雲端」

**有圖或影片**：把檔案直接拖進這個資料夾（檔名隨便）→ 雙擊「新增一篇」，它會自動幫它們編號並開好文案視窗 → 寫 → 存檔 → 雙擊「同步到雲端」

## 規則

| 項目 | 規定 |
|---|---|
| 編號 | 決定發布順序，「新增一篇」會自動編，不用自己想 |
| 文案 | 簡體寫沒關係，同步時自動轉成繁體（台灣用詞） |
| 長度 | 一律切成一串：第一篇是 40 字以內的鉤子，後面每篇約 180 字 |
| 話題標籤 | 寫在文案裡，固定用 #黃金海岸生活，一篇只認一個 |
| 圖片 | jpg、png。HEIC 同步時自動轉檔 |
| 影片 | mp4、mov，最長 5 分鐘。GIF 不行 |
| 數量 | 一篇最多 20 個圖片或影片 |

## 發布時間

每天 **3 串**，在布里斯本時間 8 點到 22 點之間，每串至少間隔 4.5 小時。

同一串裡的每篇之間也會隨機停 40～90 秒，避免看起來像機器連發。

程式每小時檢查一次，GitHub 偶爾跳過也沒關係，下個小時會自動補上。

發完的檔案自動移到 `posted/`，並記進 `posted/發布記錄.csv`。沒東西就不發，不會出錯。

## 其他

- `工具/`：程式和說明，平常不用開
- `原檔備份/`：HEIC 轉檔前的原始檔
- 金鑰 60 天到期，每月 1 號和 15 號自動續期，不用管
